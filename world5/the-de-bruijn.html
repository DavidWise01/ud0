THE DE BRUIJN SEQUENCE one word that holds every pattern once — a perfect-hash for bit positions

A De Bruijn sequence B(2,n) is a cyclic string of 2ⁿ bits in which every n-bit pattern appears exactly once as a window. That completeness makes it a perfect hash: multiply an isolated single bit by the magic De Bruijn constant, read off the top n bits, and index a tiny table — instantly recovering which bit was set, with no loop and no branch. It is how you find the lowest set bit in one multiply. The demo grounds the property the trick stands on: slide every 3-bit window over B(2,3) and watch each pattern 0..7 appear once.

THE TECHNIQUE every n-bit window appears once ⇒ a perfect hash of positions

The demo slides all eight 3-bit windows across B(2,3)=0x1D and shows they are a permutation of 0..7 (sum 28, XOR 0) — the completeness the bit-index trick exploits: live demo

RECOMMEND FOR I-13 the completeness property, on the compiler

  
On the canonical compiler, the eight 3-bit windows of B(2,3) come out as 5,6,7,3,1,0,4,2 — a permutation of 0..7 (sum 28, XOR 0):

  
$ i13 run tk_debruijn.i13   # 3-bit windows of 0x1D = 00011101
RUN OK · 96 step(s) · peak stack 3 · call depth 0
w0..w7 = 5 6 7 3 1 0 4 2
sum = 28      -- 0+1+...+7
xorall = 0    -- 0^1^...^7
perm = 1      -- every 3-bit pattern once: a perfect hash

  
Recommend as a NULL — and note its gate is encoding (B44), not resource. The De Bruijn bit-index trick works by choosing a clever codeword (the magic constant) whose windows enumerate every pattern once; the position it recovers is a property of that relabeling, not of the value — a different De Bruijn constant gives the same answers through a different table. That is the encoding gate: a property of the representation that moves under a change of code. NULL. It is the batch’s most beautiful construction and a clean second gate to point at, distinct from the resource cases around it.
