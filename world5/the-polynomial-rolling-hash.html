THE POLYNOMIAL ROLLING HASH a string as a number in base p

Read a string as a polynomial in a base p: h = the string’s digits in base p mod m. The trick that makes Rabin-Karp fast: to slide the window one step you remove the front and add the back in O(1) — no re-reading. Here rolling the window “hi” forward over “hit” gives exactly the hash of “it”: 3371 == 3371.

THE TECHNIQUE h = (h·p + c) mod m

The demo hashes a window, then rolls it and checks the result matches a fresh hash: live demo







  
HISTORY & CREDIT Rabin & Karp · 1987

  
“Rolling hashes are approximate.” — the hash is exact; only the string match after a hash hit needs a verify (to rule out a collision). cited

  
the polynomial · h = h·p + c builds the number left to right.
the roll · subtract the front’s c·pⁿ⁻¹, multiply, add the new byte — O(1).
1987 · Richard Karp & Michael Rabin, “Efficient randomized pattern-matching algorithms.”

RECOMMEND FOR I-13 the roll, on the compiler

  
On i-13, rolling “hi”→“it” over “hit” matches the direct hash of “it” (p=31, m=1e9+7):

  
$ i13 run hs_polyroll.i13
RUN OK · 135 step(s) · peak stack 7
h_hi            = 3329
rolled          = 3371   -- remove 'h', shift, add 't'
h_it            = 3371   -- direct
rolling_matches = 1

  
Recommend as a NULL — an identity (B39) + arithmetic (B40). That the rolled hash equals the direct hash is an algebraic identity (Horner’s rule mod m), not a property two mechanisms can differ on; the roll is a cheaper path to the same pinned value (B40). NULL.
